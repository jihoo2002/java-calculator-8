# java-calculator-precourse

---

## 계산기 흐름
1. 프로그램이 `"덧셈할 문자열을 입력해 주세요."`라는 메시지를 출력한다.
2. 사용자가 문자열을 입력한다.
3. 입력값을 기본 구분자(쉼표, 콜론) 또는 커스텀 구분자를 기준으로 분리한 뒤, 각 값을 `Long` 타입으로 변환한다.
4. 변환된 숫자들을 모두 더한 결과를 반환한다.

---

## 구현 기능 목록
- 입력 문자열의 숫자를 모두 더한 합계 계산
- 기본 구분자 사용: 쉼표(`,`)와 콜론(`:`)
- 커스텀 구분자 지원: `"//[구분자]\n숫자들"` 형식
- 숫자 범위: `Long` 타입으로 처리

###  예외 메시지 관리
- 모든 예외 메시지는 `ErrorMessage` 클래스에서 중앙 관리
- 상수는 `Constants` 클래스에서 중앙 관리

### 언제 예외를 던지는가

- 입력값이 `null`이거나 빈 문자열인 경우
- 입력된 숫자 중 음수가 포함된 경우
- 커스텀 구분자의 형식이 잘못된 경우
- 커스텀 구분자가 하나 이상인 경우
- 허용되지 않은 기본 구분자가 사용된 경우
- 숫자 목록 중 공백이거나 `null` 값이 포함된 경우

## 프로젝트 구조
- **domain**
    - `Calculator` 클래스 : 실제 계산 로직을 담당하며, 숫자들을 더하는 연산 수행
- **parser**
    - `CalculatorNumberParser` 클래스 : 문자열을 숫자 리스트로 변환
- **validator**
    - `CalculatorInputValidator` 클래스 : 입력값 검증 담당 (빈 값, 음수, 구분자 형식 등 체크)
- **splitter**
    - `CalculatorInputSplitter` 클래스 : 기본 구분자(쉼표, 콜론) 및 커스텀 구분자를 이용해 문자열 분리
- **util**
    - `Constants` 클래스 : 상수 메세지 관리
    - `ErrorMessage` 클래스 : 예외 메시지 관리
- **service**
    - `CalculatorService` 클래스 : 문자열 입력을 검증하고 숫자로 변환한 뒤 합계를 계산하는 흐름 관리 서비스 계층
- **view**
    - `CalculatorView` 클래스 : 사용자 입력 및 결과 출력을 담당하는 뷰 계층

- **Application** : 프로그램의 전체 흐름을 관리

## 설계에 대해서 고민했던 부분들
첫번째 고민 
> 클래스를 여러 개로 나눠야 하는 가

에 대한 고민이 들었습니다. 그동안 Spring을 이용한 프로젝트를 하면서 너무나 익숙하고, 당연시 된
클래스 나누기 (Controller, service, repository 계층 등등),,에 대해서
다시 의심해보기로 했습니다. 도대체 왜 나눌까?하고요.<br>

고민 끝에 내린 결론은 그래도 `클래스를 나누자!`였습니다. <br>
제가 찾은 이유는 역할을 다하고 있는 각각의 클래스를 나누는 방법이 구현하기 가장 편리하고 좋은 방향이라는
생각이 들었습니다. 구현하다가 이 로직은 여기에 있었지!하며 찾기도 편리하다고 느꼈고요<br>

다만 이번 구현에서 `service` 클래스가 과연 ‘서비스’라는 이름을 붙일 만큼의 그 역할을 하는지에 대한 의구심이 조금 있습니다
앞으로의 프리코스를 진행하면서 각 클래스가 제가 책임을 부여한 그 역할 그대로의 성질을
띠고 있는 지, 제 역할만 다하고 있는 지에 대한 실력을 기를 예정입니다

두번째 고민
> 상수는 하나의 클래스에 모아야 하는가

상수를 사용하는 위치마다 직접 선언할지,아니면 
상수들을 하나로 모으는 클래스를 만드는 것이 좋을 지에 대한 고민이 들었습니다. 

처음에는 각 클래스 내부에 필요한 상수만 두었지만,  
중복된 상수가 늘어나면서 비효율적인 것 같다라는 생각이 들었습니다.  
그리하여 상수 클래스를 선언하여 중복된 상수들을 상수 클래스에 모으게 했는데
여기서 또 의문이 든건 그럼 `중복되지 않은 상수들을 각 클래스에 선언하는 것이 적합한가?` 였습니다.

상수 클래스가 구현이 되어있는데 중복되지 않는 상수라 해서 각 클래스에 또 명시한다면
상수들이 중구난방으로 비춰지진 않을까 하는 생각에 코드의 일관성을 위해
모든 상수를 `Constants` 클래스에 모아두는 식으로 구현하게되었습니다.

다만 **중복되지 않는 상수**까지 각 클래스에 따로 두는 것이 맞는가에 대한 고민은 여전히 있습니다.  

세번째 고민
> 예외 처리는 어디서 이루어져야 하는가

예외 처리 또한 상수와 마찬가지로 `어디에서 이뤄져야 적합한 지`에 대한 의문이 들었습니다.<br>
예외 처리를 각 클래스 내부에서 수행할지, 아니면 예외 전용 클래스를 만들어 분리할지에 대한 고민을 하였는데,
저는 예외 처리 로직을 한 곳에서 관리하는 방법을 선택하였습니다.

예외 로직을 한 곳에서 관리함으로써 리팩토링 시에 빠르게 위치를 파악할 수 있고,  
예외 처리 책임이 명확히 분리되는 장점들 때문에 이 방법을 선택하게 되었습니다.
